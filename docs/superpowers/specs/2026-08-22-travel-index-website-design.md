# 여행지수 웹사이트 — 설계

상태: 설계 승인, 구현 전 (2026-08-22)

## 배경

기존 `.claude/skills/여행지수/SKILL.md`는 물어볼 때마다 그때그때 실시간 조사해서 Artifact 리포트를 만드는 방식(작동 확인됨, 부산-오사카 2026년 9월 테스트 총점 54점). 이를 넘어 언제든 접속해서 조회할 수 있는 실제 웹사이트로 확장하기로 함.

- Artifact(비공개 웹페이지) 방식은 CSP 때문에 외부 API를 실시간으로 못 불러서 기각. **실제 호스팅 웹사이트**로 결정.
- 호스팅 계정 없음 → Vercel 사용하기로 결정 (가입은 사용자가 직접).
- 공개 URL이 되는 것은 인지하고 있으며, 비밀번호로 접근을 막기로 함.

## 점수 로직 (기존 스킬에서 그대로 이식, 변경 금지)

6개 요소, 가중치 고정:

| 요소 | 비중 |
|---|---|
| 항공권 가격 | 20% |
| 성수기/혼잡도 | 20% |
| 환율 | 20% |
| 날씨 | 15% |
| 기온 | 15% |
| 호텔 가격 | 10% |

등급 구간: 80~100 최적기 / 65~79 좋음 / 50~64 보통 / 35~49 비추천 / 0~34 최악.

요소별 0~100 환산 기준은 `.claude/skills/여행지수/SKILL.md`에 확정된 그대로 사용 (사용자가 재조정 제안을 거부한 바 있음, 다시 건드리지 말 것).

## 아키텍처

Next.js 웹앱, Vercel 호스팅. 사용자가 여행지·시기(·출발지, 기본 부산 김해공항 PUS) 입력 → 6개 요소 점수 계산 → 결과 페이지 표시.

## 데이터 흐름 — 접근법 B (하이브리드, 확정)

Amadeus API 완전 자동화(접근법 A: 가입+OAuth 토큰 관리+국내 LCC 정확도 이슈)는 사용자가 "복잡해서 별로"라며 기각. 하이브리드로 확정:

| 요소 | 방식 |
|---|---|
| 환율 | Frankfurter.app (무료, 키 불필요) — 방문 시 실시간 호출 |
| 날씨/기온 | Open-Meteo (무료, 키 불필요) — 방문 시 실시간 호출 |
| 성수기/혼잡도 | 정적 캘린더 데이터, 도시별로 미리 작성해 repo에 저장 |
| 항공권/호텔 | Claude가 매일 1회 Google Flights/호텔 사이트를 브라우저 자동화로 조사해서 데이터 파일에 기록 → 웹사이트는 그 값만 읽음 (최대 하루 지연, 대신 API 가입/OAuth 불필요, Google Flights 직접 조회라 정확도 높음) |

## 저장소

별도 DB 계정 없이 repo 안 JSON 파일로 관리. 매일 크론(Claude 스케줄 작업)이 항공권/호텔 조사 후 git commit → Vercel 자동 재배포.

## 접근 보호

정식 로그인 대신 단순 공유 비밀번호 게이트 (개인용이라 이 정도로 충분, YAGNI 원칙). 비밀번호는 환경 변수로 관리.

이 프로젝트 관련 작업 로그는 Notion "작업 로그" DB에 기록 (인증 정보: `C:\Users\PC\.claude\notion_credentials.json`, CLAUDE.md의 "Notion 작업 로그" 절 참고). 프로젝트 속성은 "여행지수"로 남길 것.
